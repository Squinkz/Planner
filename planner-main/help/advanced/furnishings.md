# Adding custom furnishings

Furnishings use a JSON definition for their properties and SVG artwork for their appearance.

| Folder | Contents |
|---|---|
| `furnishings/definitions/` | Built-in definitions |
| `furnishings/definitions_user/` | User-created definitions |
| `furnishings/images/` | SVG artwork |

Restart Planner after manually adding or editing files. Furnishings created through Planner appear immediately.

All dimensions and positions use **millimeters**. A definition’s filename, without `.json`, is its key. Other definitions use this key when referencing it.

## Definition parameters

| Parameter | Description |
|---|---|
| `name` | Display name |
| `image` | Artwork filename from `images/`, without `.svg` |
| `width`, `length` | Default dimensions. Both must be greater than zero |
| `icon` | Optional SVG filename for the catalogue icon, without `.svg`. `null` uses the furnishing artwork |
| `category` | Category name, or a list of names to appear in several categories |
| `keywords` | Additional search terms, supplied as text or a list |
| `inherits` | Another definition’s key to inherit its properties |
| `children` | Components of a compound furnishing |
| `embeddedFurnishings` | Embedded component definitions, generated by Planner when needed to keep reusable arrangements self-contained |

For example:

```json
{
    "name": "Writing Desk",
    "image": "writing_desk",
    "width": 1400,
    "length": 700,
    "category": ["Office", "Bedroom"],
    "keywords": ["work", "study"]
}
```

Names, categories and keywords are searchable. Furnishings without a category appear under **Miscellaneous**.

### Inheritance

Use `inherits` to make a variation of an existing furnishing:

```json
{
    "inherits": "desk",
    "name": "Large Desk",
    "width": 1600
}
```

Omitted properties come from the parent. Supplied properties replace them, including category, keyword and child lists. Use `[]` to clear inherited keywords or children.

Definitions without a parent receive their defaults from `null.json`.

## Compound furnishings

A compound combines several furnishings into one arrangement. Add a `children` list, with each child referencing another definition.

| Child parameter | Default | Description |
|---|---|---|
| `furnishing` | Required | Referenced definition key |
| `x`, `y` | `0` | Center position. Positive X is right; positive Y is up |
| `angle` | `0` | Counterclockwise rotation in degrees |
| `width`, `length` | Referenced dimensions | Child dimensions |
| `scale` | `1` | Positive uniform scale. Use this instead of explicit dimensions |
| `zIndex` | `0` | Drawing order. Higher values appear on top; later children win ties |
| `flipHorizontal` | `false` | Mirror the child horizontally |
| `flipVertical` | `false` | Mirror the child vertically |
| `fixedSize` | `false` | Keep the child’s size as the compound grows |

```json
{
    "name": "Desk and Chair",
    "category": "Office",
    "children": [
        {
            "furnishing": "desk"
        },
        {
            "furnishing": "chair_dining",
            "x": 0,
            "y": -650,
            "angle": 180,
            "fixedSize": true
        }
    ]
}
```

The children’s combined bounds determine the compound’s default dimensions. Their positions share one origin, and Planner centers the finished arrangement automatically.

Compounds can contain other compounds. Empty space between children does not count as a collision.

### Fixed-size children

With `fixedSize` enabled, a child keeps its authored dimensions while the compound grows. Its center still moves with the arrangement.

When the compound becomes smaller than its default size, fixed children shrink uniformly using the smaller width or length scale. Any explicit child dimensions or `scale` establish the size being preserved.

## SVG artwork

Use these settings when preparing your graphics:

| Setting | Value |
|---|---|
| Document bounds | A valid numeric `viewBox` |
| Outlines and foreground | Pure black: `#000000` |
| Filled surfaces | Pure white: `#ffffff` |
| Transparent areas | `fill="none"` |
| Stroke width | `1` |
| Vector effect | `non-scaling-stroke` on stroked shapes |
| Maximum file size | 8 MiB |

Planner replaces black and white with the active theme’s colors. Its furnishing line-weight setting controls the rendered stroke thickness, while dash patterns, caps and joins retain their authored style.

Keep artwork self-contained. External files and network references are not supported. Embed any required raster images as PNG, and remove unused tracing images.

### Special object IDs

You can assign these IDs through Inkscape’s **Object Properties** panel. No XML editing is needed.

| ID | Purpose |
|---|---|
| `planner-bounds` | Defines the furnishing’s physical dimension box |
| `planner-fixed` or `planner-fixed-…` | Keeps a detail at its default physical size as the furnishing grows |

#### Physical bounds

Use `planner-bounds` when artwork extends beyond the furnishing’s stated dimensions, such as cabinet handles.

Draw a rectangle around the physical body and give it the ID `planner-bounds`. You can hide it in Inkscape; Planner reads hidden markers and never draws the marker itself.

Planner fits this box to the definition’s width and length without clipping protruding artwork. Selection handles, dimensions, snapping and collisions use the stated dimensions.

Paths also work. Planner uses their minimum and maximum extents as a rectangular box, rather than following their shape.

#### Fixed-size details

Give a shape or group an ID such as `planner-fixed-magazines` to stop it stretching with the furnishing.

Its midpoint moves with the furnishing, but its geometry keeps its default size and proportions as the furnishing grows. Below default size, it shrinks uniformly using the smaller width or length scale.

Mark a group to keep its contents together. Mark separate objects if their centers should spread apart as the furnishing grows. For nested markers, the outermost marked group takes precedence.

Fixed-size details do not replace `planner-bounds`.

### Lettering

Keep lettering as SVG `<text>` rather than converting it to paths.

Planner uses the canvas theme’s `labelFont`, keeps lettering centered on its authored position, and holds it upright as the furnishing rotates. Text shrinks as needed for smaller furnishings without stretching out of proportion.

Export uses the export canvas theme’s font and the same lettering layout.
